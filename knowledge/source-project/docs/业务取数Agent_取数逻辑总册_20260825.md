# 业务取数 Agent：取数逻辑与指标合同总册

更新时间：2026-08-25。范围是本项目中可维护源码、`sql/`、`deliverables/` 和交接文档中的查询逻辑；不纳入 `node_modules/`、`build/`、`dist/`、`deploy/_qa/` 等打包或验证副本。

## 1. Agent 的使用边界

1. 默认数仓为 Doris `ywzt_ods`（MySQL 协议），只生成/执行只读 `SELECT`；不得生成 DDL、DML 或修改配置。
2. 先确认指标名称、统计日期、组织/货主、仓库、商品、渠道、单位和期望粒度；没有口径时只给候选 SQL 和待确认项，不擅自拼接不同报表逻辑。
3. 默认使用闭开时间区间：`>= start_time AND < end_exclusive`。含 `[DYNAMIC_PARAMS.*]` 或 `${where}` 的 SQL 必须由调用方替换参数后才能运行。
4. 货主 `HJXH`、成品 `sku_group='50'`、有效库存状态和有效出库状态不是全项目通用条件，只能在下列明确标为该范围的指标中使用。
5. 返回结果必须附带：SQL 文件/脚本、表与关联键、粒度、过滤、单位、计算式、数据日期和未确认假设。

## 2. 可复用的基础口径

|主题|来源和粒度|过滤/关联|计算定义|
|---|---|---|---|
|可用库存（EA）|`scm_warehous_manage`，货主+仓库+SKU|库存状态 `ZP/NULL/空`；业务占用来自 `scm_warehous_occupy` 近 60 天，按同一货主+仓库+SKU；部分报表还要求 `occupy.status != 1`|`max(在库 - 占用 - (锁定非0则锁定，否则冻结), 0)`。`stock_lock` 为字符时仅可安全转换的数值参与计算。|
|近日期库存（EA）|`scm_warehous_manage` 或 `scm_warehous_manage_3d`，仓库+SKU|生产日期 `> CURDATE()-INTERVAL 60 DAY`；3D 表取最近有数据的 `created_date` 整日快照|在库量求和。它是近生产日期在库量，不等于可用库存，可能大于可用库存。|
|箱规/箱数|`master_sku_unit`，SKU|`unit=40` 且 `ea_convert_quantity>0`|`箱数=EA数量/ea_convert_quantity`；提货项目展示向下取整，虎皮肉肠默认保留 2 位小数，零食很忙项目使用 `CEIL`。同一 SKU 多箱规时不得自行取 MAX/MIN。|
|有效出库（EA）|`scm_sales_shipment_header` + `scm_sales_shipment_detail`，日期+仓库+SKU|常用状态 `700/900/701/901`；单据类型 `JYCK/HHCK/BFCK/QTCK` 或 `SO%`；许多报表还要求单号 `HJXH%` 和 FDL 未删除|`SUM(ship_qty)`；渠道来自 `master_store`（`code=store_code`）。|
|渠道分类|出库明细+`master_store`|`type='Z004'` 为线上，`Z001` 为线下；线下社区平台 `group1='03'`，社区分销 `price_group='122'`|线下其他为 `Z001 AND NOT(group1='03' OR price_group='122')`；线上平台分组见第 4 节。|

## 3. 主生产逻辑：线下提货水位

|逻辑文件|产出/粒度|关键来源|核心口径|
|---|---|---|---|
|`sql/realtime_stock.sql`|仓库+SKU|库存、占用、SKU、仓库主数据|HJXH 成品、自有仓类型 `10/11`、排除残次仓；输出可用库存和近 60 天生产库存。|
|`sql/third_party_stock_60d.sql`|仓库+SKU|`scm_warehous_manage_3d` 最新快照|HJXH 成品近 60 天生产库存；某仓库+SKU 有该行时优先于实时库存的近日期库存，即使数量为 0。|
|`sql/offline_sales_7d_warehouse_sku.sql`|仓库+SKU（内部先按日）|出库头/明细、订单头、门店、SKU、仓库|最近 7 个完整自然日，输出线上预留、线下销量和线下日均。|
|`sql/offline_sales_7d.sql`|日期+仓库+SKU|同上|完整的渠道分拆明细；用于审计和报表，而非提货聚合结果。|
|`sql/sku_box_unit.sql`|SKU|`master_sku_unit`|有效 `unit=40` 箱规。|
|`scripts/refresh_pickup_data.py`|`data/pickup-data.json`|执行以上 SQL 并合并|输出 key 是实时库存、三方近日期库存、近 7 天销售的仓库+SKU 并集；最终再过滤成品。|

最终指标：

```text
线上预留后剩余 = max(可用库存EA - 线上近7天销量EA, 0)
线下可提货EA = min(近60天生产库存EA, 线上预留后剩余)
线下可提货箱数 = floor(线下可提货EA / 箱规)
线下日均箱数 = 线下近7天销量EA / 箱规 / 7   # 使用未取整箱数
库存天数 = floor(线下可提货箱数 / 线下日均箱数)
```

线下日均 `<=0` 时库存天数为 `--`；库存天数 `<7`、`7-14`、`>=15` 分别为不建议大量提货、正常销售、可大量提货。历史 `*_original.sql` 是原始备份，`recent_stock_60d.sql` 与 `third_party_stock_60d.sql` 当前文本逻辑相同，均不可与实时库存的“可用量”概念混称。

## 8. 仅作历史/原版保留，不得默认调用

`realtime_stock_original.sql`、`recent_stock_60d_original.sql`、`third_party_stock_60d_original.sql` 是原始版本；`sql/recent_stock_60d.sql` 与三方仓文件存在命名/内容重叠。`deploy/daily_order_report_20260729/sql/daily_order_count.sql` 是部署包内订单日报 SQL。任何 Agent 检索到这些文件时，只能将其作为历史比对材料，不能覆盖第 3 至第 6 节的现行定义。

## 9. Agent 的强制追问与拦截规则

1. 用户问“库存”时，必须确认是：在库、可用、近 60/75 天生产库存、在途，还是线下可提货；不能默认选一个。
2. 用户问“销量/出库”时，必须确认是实发出库还是社区平台订单替代、线上/线下范围、按发货日还是订单创建日，以及是否包含当天。
3. 用户问“箱数”时，必须说明取整策略并校验箱规；同 SKU 多箱规或缺箱规时输出异常清单，不自动选值。
4. 用户问“可用天数/周转”时，必须指明分母是近 7 天线下日均、近 30 天全渠道日均或其他；分母为 0 时返回空/无动销，不制造无限值。
5. 商品范围、仓库范围、货主、删除标记、状态字段、快照日期、DMS 与 Doris 的来源边界都必须显式写进 SQL/结果说明。
6. 任何将 DMS、Excel 静态数据、3D 快照和实时 Doris 数据混合的需求，先返回可对账的分源结果及合并规则，待业务确认后才给最终总数。
