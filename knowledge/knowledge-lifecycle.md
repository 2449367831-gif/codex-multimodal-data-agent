# 知识迭代、反馈与发布

运行时只读取一个已经发布且不可变的 `release_id`。Doris 元数据扫描、用户反馈和人工修正都先进入候选区，不能直接修改当前发布版本。

## 自动迭代边界

可以自动写入 `observations/` 的内容包括表和字段的实际结构、最大业务时间、枚举观测、空值率、重复键率和扫描时间。这些数据用于差异与影响分析，不是业务合同。

公式、来源、Join、粒度、日期含义、单位、过滤范围、参数默认值和口径别名都属于受保护字段。自动任务只能创建候选版本，并附上受影响指标、SQL 差异、黄金问题结果和对账证据；业务负责人批准后才能进入发布清单。

## 多口径路由

同一 `business_concept` 可以有多个 `variant`。Agent 先按明确口径和结构化适用条件过滤候选，再匹配别名。候选不能唯一确定时，使用合同中的 `clarification.ambiguity_group` 生成一组完整的结构化选择题，在同一轮一次性发给用户；不得逐个追问，也不得要求用户用自由文本补充。向量或全文相似度只用于召回候选，不得直接决定口径。

## 反馈闭环

每条反馈都关联原始 `query_audit_id`、知识发布版本、指标版本、参数、鲜度和校验结果。已接受回答只能增加统计；路由、参数或定义纠正会生成候选黄金问题或候选合同。任何反馈都不能改写历史发布和历史审计。

## 测试持续学习

聊天服务在每次请求完成、失败、阻断或等待口径选择后，向安装实例主体隔离的学习账本写入一条受控事件。事件只保存经过长度限制和脱敏的问题摘要、问题类别、生命周期状态以及是否形成业务结果；不保存 SQL、结果行、凭据、工具明细或模型完整上下文。重复请求按 `request_id` 幂等，反馈按请求覆盖更新，避免反复点击造成虚假统计。

学习账本会自动把重复问法、失败类别、口径修正和新口径提交聚合为待审核候选，并在本机受保护的 `var/learning-digests/` 下生成 JSON/Markdown 摘要。浏览器的“学习总结”只显示计数和类别；候选问法与定义原文不通过用户接口回传。

候选不会进入 Codex 运行时，也不会自动改写 `metrics/`、`sources/` 或 `profiles/`。业务负责人需要先审阅候选，补齐业务定义、来源表、Join、粒度、时间窗口、单位、排除规则、鲜度和对账证据，再运行 Schema、静态只读、黄金问题和回归门禁，最后按发布清单生成新版本。可用以下本机维护命令重建摘要，命令默认只输出计数：

```text
python -m tools.rebuild_learning_digest --all
python -m tools.rebuild_learning_digest --principal-hash <principal_hash>
```

## 发布流程

1. Doris 扫描或反馈产生 observation/event。
2. 差异分析生成候选合同版本和候选发布清单。
3. 运行 Schema、跨引用、SQL 只读、黄金问题和影响测试。
4. 业务语义变化由业务负责人审批；来源语义变化同时由数据负责人审批。
5. 发布器为精确合同、来源、模板、规则和黄金集写入 SHA-256；最终清单摘要经审批后写入独立部署密钥。
6. 发布器原子切换 `current_release` 指针，运行时同时校验清单内文件摘要、实际缓存字节摘要和外部 `AGENT_TRUSTED_RELEASE_SHA256`，查询审计记录准确的 `release_id` 与合同版本。
7. 回滚只恢复上一发布指针及其受信摘要，绝不修改历史清单与查询记录。

当前 `releases/candidate-0.1.0.yaml` 只是候选清单，不代表已通过业务审批，也不能作为生产路由版本。
