# 业务结果表格展示契约

查询结果分为两层：`business_result` 是可读的文字摘要，`business_table` 是面向用户的聚合表格。两者都只在 Doris 查询成功且通过业务校验后返回；执行过程仍然只展示阶段状态，不展示 SQL、物理表名、字段名、原始结果行或审计内容。

## 当前支持的表格

| 路由 | 展示内容 | 主要列 |
| --- | --- | --- |
| 销售出库按仓 | 每个有效仓库的实际销售出库汇总 | 仓库、实际销售出库 |
| 销售出库 Top SKU | 按销售出库数量降序的 SKU 排名 | 排名、商品、SKU、销售出库、订单数 |
| 历史库存周转 | 公式的可读分解 | 区间末成品库存、实际销售出库日均、库存周转 |
| 生产批次库存 | 指定生产日期和仓库的库存对照 | 生产日期、仓库、当前库存、实际可用、历史快照库存、快照日期 |
| 实际入库按仓 | 有效完成入库的数量和重量 | 仓库、入库数量、入库吨数 |
| 入库量最高 SKU | 入库数量最高的 SKU | 商品、入库数量、入库吨数 |

## 边界

- 语义运行时先完成口径、范围、粒度、时间窗口、鲜度和对账校验，再生成展示表。
- BFF 根据 `table_id` 选择固定列定义；输入中的未知列、额外单元格和任意标题不会进入公共响应。
- 公共响应最多返回 100 行，数值必须是有限的非负聚合值，单位来自受控集合。
- 浏览器再次验证列键、列标签、单位、文本长度和总字节数；刷新恢复使用同一套验证。
- 新增指标时，应先在语义运行时生成展示用聚合字段，再同时登记后端表格 schema 和前端列定义。不要把 Doris 原始结果对象直接挂到 `business_table`。

## 前端呈现

- 摘要区展示总量、行数或统计天数；数值右对齐并使用千位分隔。
- 表头固定层级、表体隔行底色，空结果显示明确空态。
- 桌面端保持 Codex 工作台布局；窄屏使用局部横向滚动，Top SKU 在移动端保留数量列并把 SKU 编码放到商品下方。
- 公共页面继续使用皇家小虎真实 logo 和头像资产，结果卡片沿用现有金色、棕色、青绿色令牌。
