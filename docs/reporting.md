# 数据报告模块

## 使用方式

1. 先用自然语言或上方的规则取数完成一次查询。
2. 只有结果状态为“查询完成”、且存在实时数据表时，每张结果表的“导出”工具栏旁才显示“生成报告”。
3. 可在同一工具栏输入报告要求，例如“给领导看，突出异常仓和建议”；不填写时由模型按供应链业务默认结构生成。
4. 服务端先读取本次查询的服务器回执，再把已校验的数据交给独立的报告模型生成结论、解读和建议，最后生成网页、PDF、Word、Excel、CSV、PNG 六种文件。
5. 点击对应格式下载。文件链接绑定当前安装实例和当前会话，默认短期有效。

## 生成边界

- 报告只能使用已完成、真实 Doris 查询、未截断、已通过展示校验的结果。
- 查询失败、后端拒绝、查询服务不可用、空结果和不完整分页不会生成报告。
- 分页结果生成报告前会由服务端完整取回并校验行数，不接受浏览器回传的表格作为事实来源。
- 报告中的数值来自结果表；模型只负责报告结构、业务解读和建议，不能查询数据库、改写表格或编造数字。
- 模型报告生成失败时，系统仍可生成带真实数据表的基础报告，并在数据处理说明中保留可核验内容。
- 报告默认包含：核心结论、背景与目标、数据概览、深入分析、结论与建议、数据处理说明。
- 报告不包含 SQL、物理表名、字段名、凭据、审计内容或内部执行日志。

## 内部接口

```text
POST /v1/reports
GET  /v1/reports/files/{file_id}
```

请求体通过 `conversation_id` 和已完成查询的 `request_id` 绑定数据源：

```json
{
  "conversation_id": "c_...",
  "request_id": "...",
  "title": "业务数据分析报告",
  "audience": "供应链业务",
  "instructions": "给领导看，突出异常和建议",
  "formats": ["html", "pdf", "word", "excel", "csv", "png"]
}
```

报告文件保存在短期文件存储中，下载时再次校验安装实例、会话和文件归属。
